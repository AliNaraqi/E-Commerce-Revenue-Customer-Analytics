# Power BI build guide

Everything Power BI needs is generated by this repo: a tested star schema
(`dashboard/model/*.csv`) and the complete measure set (`dashboard/measures.dax`).
This file is the assembly order.

> **Status.** An interactive dashboard covering the same four pages is already
> published at https://claude.ai/code/artifact/35540dfb-e73e-4ddf-a023-9d0d5373b71e — see
> `dashboard/interactive_dashboard.html`. The `.pbix` and its screenshots are
> **not** in this repo.
> Power BI Desktop is Windows-only and this analysis was built on macOS, so the
> report could not be authored or captured here. Everything upstream of the
> `.pbix` is finished and verified; the remaining work is the ~1 hour of
> clicking described below. `outputs/figures/*.png` carry the same findings in
> the meantime.

## 1. Load

**Get Data → Folder →** `dashboard/model` → *Combine & Load*. Six tables arrive:

| Table | Grain | Rows |
| --- | --- | --- |
| `fact_orders` | one row per order | 99,441 |
| `fact_order_items` | one row per order line | 112,650 |
| `dim_customer` | one row per `customer_unique_id` | 93,358 |
| `dim_product` | one row per product | 32,951 |
| `dim_seller` | one row per seller | 3,095 |
| `dim_date` | one row per calendar day | 774 |

Regenerate them any time with `python scripts/export_powerbi_model.py`.

## 2. Model

Create these relationships — **all single-direction, many-to-one**:

| From | To | Cardinality |
| --- | --- | --- |
| `fact_orders[customer_unique_id]` | `dim_customer[customer_unique_id]` | many-to-one |
| `fact_orders[order_date]` | `dim_date[order_date]` | many-to-one |
| `fact_order_items[order_id]` | `fact_orders[order_id]` | many-to-one |
| `fact_order_items[product_id]` | `dim_product[product_id]` | many-to-one |
| `fact_order_items[seller_id]` | `dim_seller[seller_id]` | many-to-one |
| `fact_order_items[order_date]` | `dim_date[order_date]` | many-to-one |

Then **Table tools → Mark as date table** on `dim_date[order_date]`. Without
this, every time-intelligence measure (`GMV PM`, `GMV MoM %`, `GMV YTD`)
returns blank.

**Do not set any relationship to bi-directional.** The two date relationships
plus a bi-directional filter create an ambiguous path between `fact_orders` and
`fact_order_items`; Power BI resolves it silently and order counts drift.

**Hide from report view:** every `*_id` key column, and `is_eligible`. They are
model plumbing — exposing them invites someone to drag a key onto a visual and
break the grain.

## 3. Measures

Paste each definition from `dashboard/measures.dax` via **Modeling → New
measure**. Set formatting as you go:

| Measure group | Format |
| --- | --- |
| `GMV`, `Freight`, `AOV`, `GMV per Customer` | Currency, `R$`, 0 decimals (2 for AOV) |
| `Orders`, `Items Sold`, `Active Customers` | Whole number, thousands separator |
| every `… Rate`, `… %` | Percentage, 1 decimal |
| `Avg Review Score`, `Review Gap` | Decimal, 2 places |

## 4. Validate before building any visual

Drop a card for each measure with no filters applied and check it against
`outputs/kpis.json`. **If a number disagrees, fix the model — do not adjust the
measure to match.**

| Measure | Expected |
| --- | --- |
| `Orders` | 96,478 |
| `GMV` | R$13,221,498 |
| `AOV` | R$137.04 |
| `Active Customers` | 93,358 |
| `Repeat Purchase Rate` | 3.0% |
| `On-Time Rate` | 93.2% |
| `Avg Review Score` | 4.16 |
| `Avg Review — On Time` | 4.29 |
| `Avg Review — Late` | 2.27 |

The most likely cause of a mismatch is a bi-directional relationship or a
missing `is_eligible` filter.

## 5. Pages

Four pages, each answering named questions from the README.

### Page 1 — Executive Overview (Q1, Q3)
- KPI cards: `GMV`, `Orders`, `AOV`, `Active Customers`, `On-Time Rate`, `Avg Review Score`
- Line chart: `GMV` by `dim_date[year_month]`
- Column chart: `Orders` by `dim_date[year_month]`
- Slicer: `dim_date[year_month]`, defaulted to `in_trend_window = 1`
- Text box carrying the `GMV Caption` wording

Put GMV and orders in **two charts, not one with two y-axes** — a dual axis lets
the reader infer a relationship from an arbitrary scale choice.

### Page 2 — Customer Insights (Q4, Q7)
- Cards: `Repeat Purchase Rate`, `GMV per Customer`, `New Customers`, `Returning Customers`
- Bar chart: `GMV` and `Active Customers` by `dim_customer[segment]`
- Scatter: `recency_days` (x) vs `gmv` (y) by segment, with a point cap
- Table: segment × customers × GMV × GMV per customer

### Page 3 — Products & Regions (Q1, Q2)
- Bar chart: `GMV` by `dim_product[category]`, Top-15 filter
- Map or bar: `GMV` by `fact_orders[customer_state]`
- Table: category × `GMV` × `GMV % of Total` × `Avg Review Score`

A map keyed on two-letter Brazilian state codes needs the column's **Data
category** set to *State or Province*, otherwise Bing geocodes `PA` to
Pennsylvania.

### Page 4 — Delivery & Satisfaction (Q5, Q6)
- Cards: `On-Time Rate`, `Late Orders`, `Avg Days to Deliver`, `Review Gap (On Time − Late)`
- Line chart: `On-Time Rate` by `year_month`
- Clustered bar: `Avg Review Score` by on-time vs late
- Matrix: `customer_state` × (`Late Rate`, `Avg Days to Deliver`, `Avg Review Score`)
- Text box: *"Associations are descriptive. Product mix, shipping distance and
  seller are not controlled for."*
